# ガバナンス(新しいツールを足すときのルール)

目的: 単発で作るツールが「バラバラの小さなアプリ」にならず、**データが残り、ツール同士がつながり、AIからも扱える**状態を保つ。
**ツールの実装を担当する Claude は、先に [TOOL-SPEC.md](TOOL-SPEC.md)(触ってよい範囲・納品形式)を読む。** 台帳は [tools/README.md](tools/README.md)。
ルールは少数に絞り、機械で検査できるものは `npm run check` が検査する。

## 1. 置き場所の決め方(迷ったらこの順)
| やりたいこと | 使うもの |
|---|---|
| 予定・やること・目標 | 既存の **タスク/プロジェクト/予定**(新しい入れ物を作らない) |
| 願望・いつかやりたい | **やりたいこと** |
| 文章・図・考えごと | **メモ** |
| 毎日の記録 | **習慣** / **振り返り** |
| それ以外の「新しい種類のデータ」(読書、買い物、体調、家計…) | **コレクション**(下記) |
| 画面だけが違う・集計だけしたい | **拡張**(`src/extensions/`)で、既存データを読んで表示 |

新しい種類のデータだと思っても、まず「既存の項目+タグ」で足りないかを考える(足りるなら作らない)。

## 2. 新しいデータの種類 = コレクション
1. `src/collections/<id>.ts` に `defineCollection()` でスキーマを書く(ひな形 `_example.ts`)。
2. `src/collections/index.ts` に1行追加する。
3. これだけで、**同期・バックアップ・汎用の一覧/編集画面・検索・AI(MCPの `collection_*`)** が使える。専用画面が必要なら `customView: true` にして拡張で画面を作る。

守ること:
- `id` は一度決めたら変えない(データのキー)。スキーマを非互換に変えたら `version` を上げ、`docs/CHANGELOG-DATA.md` に1行残す。**項目の削除・型の変更は避け、追加だけにする**。
- 他の項目との関係は **`ref` 型(`{kind, id}`)** で持つ。ID文字列をテキストに埋め込まない。`kind` は `task / project / event / habit / note / wish` かコレクションID。
- 日付は `YYYY-MM-DD`、時刻は分(0〜1439)または `HH:MM`、金額などの単位は項目名かラベルに明記する。
- 個人情報・秘密(パスワード、トークン、口座番号)は保存しない。

## 3. 画面(拡張)のルール
- 色・余白・角丸は `src/theme/tokens.css` の変数だけを使う(`#rrggbb` を書かない)。部品は `base.css` のクラス(`.btn .field .rows .sheet` など)を使う。
- データの保存は store / コレクション経由のみ。`localStorage` などに自前で保存しない(同期されず、AIにも見えなくなる)。
- 画面は `registerView`、「今日」の部品は `registerWidget`、操作は `registerCommand` で登録する。直接 `App` を書き換えない。
- 認証情報(`settings.ghToken` など)に触れない。

## 4. AI(MCP)との整合
- **SelfDesk に書かれていることが正**。AIは推測せず、MCPで確認してから答える/変更する(`get_guide` と MCP の instructions に明記してある)。
- 新しいコレクションは、MCPコードを書かなくても `collection_*` で扱える。専用の振る舞い(計算・自動処理)が必要な時だけ `mcp/src/tools.ts` にツールを足し、**ツール説明文に「いつ使うか」を書く**。
- 削除系ツールには `destructiveHint` を付ける。

## 5. 新ツールを作る前の確認(依頼時に私=Claudeが必ず通す)
1. 既存のどのデータで足りるか(足りないなら、なぜコレクションが必要か)
2. 何を `ref` でつなぐか(プロジェクト? タスク? メモ?)
3. 「今日」画面・⌘K・MCP のどこに出すか
4. データを後から壊さずに拡張できるか(項目は追加のみ)

## 6. 検査
`npm run check` = ルール検査(`scripts/check.mjs`) + 型検査(アプリ/MCP) + テスト。push 前に実行する。CI(Actions)でも型検査とビルドが走る。
